# The Abyss — design and implementation plan

## Approved concept

The Abyss is a new underground region inside the Overworld (not a separate dimension).
The agreed vertical expansion is 192 blocks: the Overworld minimum Y moves from -64 to -256,
while the original top remains Y=319. The corresponding dimension/noise height is 576.

Suggested layers:
- Y -64 to -80: transition from Deepslate to Abyssal Stone.
- Y -80 to approximately -251: The Abyss.
- Bottom bedrock is generated by the vanilla bedrock-floor material rule at the new minimum.

## Visual identity

- Abyssal Stone is much darker than Deepslate and harder (initial tuning target: hardness 8-10).
- All ore blocks generated in The Abyss must use the Abyssal Stone as their shared texture base,
  while preserving each ore's recognizable mineral colors/patterns. Do not use standard Deepslate ore textures.
- Textures are designed at 16x16 and follow Minecraft's pixel-art style.
- Amethyst corruption appears in localized cracks, veins, and larger crystal pockets, not uniformly.
- Monumental caves should contain giant stalactites, stalagmites, columns, and open chambers.

## Ores and resources

Common Abyssal ore variants: coal, copper, iron, gold, redstone, lapis, diamond, and emerald.
They drop their normal vanilla resources. Diamonds, iron, gold, redstone, lapis, and runes should be
more available than in the surface layers; coal/copper remain moderate. Emerald remains a low-rate
resource and should ultimately respect mountain-biome behavior.

Abyssal Rune Ore reuses the existing RuneOreBlock/charge state and RuneMiningManager behavior.
Existing Rune Ore generation should be more rewarding in this region.

Transcendent Ore is the only special rare ore in The Abyss:
- Generates only inside Abyssal Stone (Y range -248 to -180 in the initial tuning pass).
- Extremely rare; initial placed-feature chance is 1 in 192 per attempt.
- Emits block light level 15.
- Always grants exactly one existing Celestial Altar Transcendency Essence.
- Silk Touch, Fortune, Mining Loot Duplication, equipment drop perks, and future duplication systems
  must not increase or bypass the one-item rule.
- It must not be chained by Vein Mining.

The Transcendent Ore reuses the existing `simpleskills:transcendency_essence` item from
`CelestialAltarContent`. This is the same catalyst already used by the Celestial Altar to
transform equipment into Transcendent rarity; the expansion must not register a second essence item.

## Skills integration

- Mining XP, Gathering Speed, durability protection, and ordinary ore behavior should remain active.
- Ordinary ores continue to receive normal Fortune/loot behavior.
- The Transcendent Ore is tagged as non-duplicable and non-vein-minable.
- Mining level 99 must still feel powerful, but Abyssal Stone should remain meaningfully harder.

## Implementation status in this source package

Implemented in this first foundation pass:
- Overworld `dimension_type` and noise settings are extended to min_y=-256 / height=576.
- Overworld density functions were extended below the old -64 floor so the new depth is not just a solid column; the vanilla cave/noise graph now remains active down toward the new bottom.
- An Overworld material rule transitions to Abyssal Stone below the transition band.
- Abyssal Stone, decorative variants, common Abyssal ore blocks, Abyssal Rune Ore,
  Transcendent Ore, and existing Celestial Altar Transcendency Essence are registered.
- Data-driven placed features add Abyssal ore veins, rune ore, amethyst-corrupted stone, and rare
  Transcendent Ore in new Overworld chunks.
- All generated Abyssal ore textures share the dark Abyssal Stone visual base.
- The Transcendent Ore is excluded from drop duplication and Vein Mining.
- The creative tab, block/item models, loot tables, tags, and six language files are updated.

Implemented in the follow-up cave pass (still requires in-game tuning):
- A dedicated low-frequency Abyss chamber noise and density mask carve larger, irregular rooms
  only in the lower region (approximately Y=-248 to -80).
- Native speleothem-cluster features generate regular, monumental, and colossal Abyssal formations. The first pass used a custom pointed-dripstone block; the later solid-block pass below supersedes it for new world generation.
- Initial formation sizes were smaller; the current target sizes are documented in the follow-up tuning section below.

Still pending:
- In-game frequency and size tuning across multiple seeds (including proof of 70-100 block chambers).
- More specialized crystal pockets and a more sophisticated spatial clustering system for amethyst.
- Mountain-biome-only emerald placement (the first pass uses a conservative low count in the Abyss).
- Full in-game generation, multiplayer, performance, and compatibility testing.

## Compatibility and testing warnings

- This modifies vanilla resource keys `minecraft:overworld` for dimension type, noise settings, and
  material rules. Datapacks or other mods that override the same resources can conflict.
- Existing worlds have already-generated bedrock at Y=-64. Do not assume old chunks will gain the
  new underground space automatically. First validate in a new world; a migration tool must be
  designed separately before promising compatibility with existing saves.
- The source ZIP provided for this work did not include Gradle wrapper/build files, so Gradle compile
  validation cannot be run from this package alone.
- All numeric ore counts, vein sizes, and rarity filters are starting balance values, not final tuning.


## Follow-up implementation — monumental caves and speleothems

- Reuse `simpleskills:transcendency_essence`, the exact catalyst already used by the Celestial Altar to transform equipment into Transcendent rarity. No second essence item is registered; `transcendent_ore` drops the existing item.
- Added a low-frequency `simpleskills:abyssal_chambers` noise field and a dedicated density function limited to Y=-248..-80. The Overworld final density combines the vanilla shape with this mask to carve broad, irregular chambers in the Abyss.
- Added a legacy `PointedDripstoneBlock` registration for the initial version; the later solid-block pass below removes it from new generation while preserving the registry entry for already-generated chunks.
- Added three native `minecraft:speleothem_cluster` features; their updated sizes and full-block material are documented in the follow-up tuning section below.
- Cave generation, colossal formation frequency, and formation density still need in-game seed testing; the provided source-only archive does not include Gradle wrapper/build files, so compilation could not be executed from this source package alone.


## Follow-up tuning — lava-free Abyss and giant solid-block formations

- The Overworld aquifer lava density now returns a value below the lava-selection threshold only from Y=-256 through Y=-80. The original `minecraft:aquifer_lava` noise remains unchanged outside this band, so upper Overworld caves keep their prior fluid behavior.
- Abyss chamber noise now uses a much larger horizontal scale and very low vertical scale, creating broad cavern volumes and long vertical shafts instead of mostly compact cave pockets. The carve threshold is wider, with a smaller detail field retained to keep the cavern edges irregular.
- Regular, monumental, and colossal formations are larger and use `simpleskills:abyssal_pillar` as both the base and column block. Their surfaces are made from full solid blocks; the pointed-dripstone block is no longer used by new world generation.
- The old `abyssal_pointed_stalactite` registry entry remains registered only for backward compatibility with chunks generated before this change. It is removed from the creative item list and is no longer referenced by the new configured features.
- As with other worldgen changes, the updated behavior applies to newly generated chunks. Lava and formations already written into existing chunks are not retroactively rewritten.


## Follow-up — grounded castle massif (November 2026)

- Castle placement is fixed at Y=-204, leaving the 122-block spire at Y=-82 and about 51 blocks of vertical foundation run to Y=-255.
- The city/foundation box extends to +/-280 X/Z. Structure-reference radius is 18 chunks (default enabled in `MixinPlugin` and configurable with `abyss_city_extended_structure_references`).
- Surface terrain uses a 43-block smoothstep drop around the central platform. The foundation radial envelope widens with depth from about 1.12x to 1.40x, reaching the world floor above bottom bedrock.
- Foundation writes are allowed at Y=-255; the existing solid-terrain check still stops the fill after four consecutive natural solid blocks.
- Abismo Preview 4.0 uses the same castle/city Java sources and moves its display floor to Y=-255. The cave envelope remains an approximation, not a full NoiseRouter simulation.
- The updated Java generator passed the local simulator compile and seed-7 generation. Full Fabric Gradle build and in-game chunk test remain required.
